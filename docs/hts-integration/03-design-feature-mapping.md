# 3. VELTRO 디자인 → HFM KOREA HTS 화면·기능 매핑표
작성일: 2026-11-19
기준: VELTRO는 **디자인 참고**이고 HFM KOREA는 **기능·데이터·인증·거래 규칙 기준**이다. 현 단계에서는 어떤 서버/DB/체결 소스도 수정하지 않는다.

## 분류 정의
- **디자인만 이식**: 외형, 비율, 간격, 탭, 색상, 키보드 포커스 등
- **기존 기능 연결**: 기존 API·데이터·핸들러를 그대로 렌더링
- **기존 UI 개선**: 현행 Electron View 중복·잘림·동기화·반응형 수정
- **대상 고유 기능 보존**: VELTRO에 없더라도 HFM 기능 유지
- **추가 개발(별도 승인)**: 자동업데이트 등 사용자 지시에는 있으나 현재 대상에 없는 기능

## 기능 호출의 소유권
- 브라우저/데스크톱은 기존 로그인된 HFM 웹 앱의 UI 또는 제한된 IPC를 이용한다.
- Electron main/preload는 서버 거래 엔진을 복제하거나 DB에 직접 접근하지 않는다.
- 권한/잔고/수수료/증거금/시세 신선도/체결·취소·청산의 최종 판단은 HFM 서버가 수행한다.
- 화면 시연용 가짜 시세·가짜 체결·가짜 회원자산 추가 금지.

## UI 단계별 최소 수정 전략
1. **동결선 정의**: `server.js`, `app-api.js`, `futures-internal-engine.js`, `stock-internal-engine.js`, `funding-api.js`, `trading-api.js`, 모든 DB 스키마 및 자산 원장 변경 금지.
2. **화면 스켈레톤만 분리**: `desktop/workspace.html`에서 좌측 탐색·상단 헤더·패널 비율을 VELTRO 원칙에 맞춰 고치되 기존 View/IPC 유지.
3. **패널 단위 CSS**: `desktop/layout.cjs`에서 차트/주문/포지션에 WTS 헤더·중복 차트·중복 주문·계좌카드가 나타나지 않도록 테스트.
4. **인증/종목 동기화 검증**: `desktop/main.js`, `desktop/workspace.js`의 기존 메시징만 검증. 새로운 주문 API 생성 금지.
5. **가독성 마감**: 가격/틱/계약/주식 단위/버튼/모달/포커스의 크기·간격을 조정.
6. **테스트**: 데스크톱 자동 테스트뿐 아니라 실제 Windows 로그인 → 차트 → 종목 검색 → 주문 → 취소 → 포지션 → 분리 창 → 종료/재실행을 별도로 검사.

## Electron 자동 업데이트 설계(분석만, 미구현)
### 현황
- 대상 패키지는 `desktop/package.json` v0.2.0, NSIS+Portable.
- 현재 CI는 `npm run dist:win`을 `--publish never`로 빌드하고 Actions Artifact에 EXE만 업로드.
- `electron-updater` / GitHub Releases 설정·메타데이터 없음; 대상 저장소 Releases 목록도 비어 있음.

### 이식 가능한 기술적 설계
1. 기존 배포 소유자 `BITMATE-del/HFM-KOREA`를 릴리스 원천으로 고정. VELTRO 릴리스 URL·owner/저장소는 **가져오지 않음**.
2. 표준 NSIS 설치형에 `electron-updater`를 검토하고 `latest.yml` + 해당 버전의 `Setup.exe` + `.blockmap`을 동일 버전의 GitHub Release로 게시한다.
3. 빌드 버전과 릴리스 태그/메타데이터가 일치하도록 CI 검사. 체크섬/HTTPS/가능한 코드서명 검증.
4. 앱 실행 시 새 버전 확인. 업데이트 다운로드 진행률을 한국어 표시. 다운로드 완료 후 '지금 재시작/나중에' 제공.
5. '나중에': 현재 프로세스 유지. 재시작은 사용자가 선택하며 정상 종료 설치 정책을 별도 검토. 사용자 몰래 주문 입력 중 종료하지 않음.
6. '지금 재시작': 다운로드 완료 시에만 `quitAndInstall`을 호출하고, 업데이트 이후 로그인·차트·주문 확인 화면을 실기기로 테스트.
7. 실패: 업데이트 오류는 주 프로그램의 로그인/거래를 막지 않고 기록·안내만. 다운로드 재시도 및 기존 버전 실행 허용.
8. portable은 설치형 NSIS 자동업데이트와 동일하게 취급하지 않는다. portable의 버전 관리/수동 교체 정책 별도 명시.
9. 강제 업데이트 기능은 요구사항 검토 대상으로만 기록하고 **기본은 선택 업데이트**.
10. 서명/릴리스 토큰/GitHub Actions 권한·브랜치 보호·롤백 정책을 확정하기 전 자동 릴리스 변경 금지.

## 단계별 합격 기준
| 단계 | 필수 증빙 |
|---|---|
| 설계 승인 | 원본 디자인 분석서, 대상 기술 분석서, 매핑표 검토 |
| UI 변경 | 동일 종목·시세·가격/손익 표시, 중복 DOM·잘림 없는 Windows 화면 캡처 |
| 주문 검증 | 테스트 회원 시장가/지정가(지원 범위), 취소·청산, 원장·잔고 정합성 |
| 업데이트 구현 | 설치형 구버전 → 새 릴리스 감지 → 다운로드 → 나중에 → 지금 재시작 → 버전/기능 확인 |
| 장애 복구 | 오프라인/손상된 업데이트/릴리스 누락에서도 기존 버전 거래 흐름 유지 |
| 최종 배포 | 실제 Windows 설치/업데이트 확인, 빌드 로그, 롤백 가능한 릴리스 보존 |

**현재 결론**: 세 문서는 개발 전 설계 자료이며, 사용자 승인 없이 코드 수정·새 API·DB 마이그레이션·자동 릴리스/업데이트는 시작하지 않았다.
